# Singularity RepoQL | OpenMausBot shared rules for Windows

These instructions apply to OpenMausBot bot workspaces under this local installation. They are instructions, not permission grants or proof a hook fired. Keep the bot persona in its own SOUL.md. Do not edit another bot's files or inherit another bot's private memories.

## Before a meaningful task

Check the actual Windows-local RepoQL index/source for relevant code and current documentation. Use existing Kanzo MCP `check_work` to identify overlapping work; obtain a real session-bound `claim_work` for shared mutations, using the existing lifecycle. No claim is required for a read-only investigation. Do not infer ownership from a displayed name, presence or an earlier session's claim. If the Kanzo broker is unavailable, stop material shared writes and explain the blocker.

## Work, gates, and nudges

Follow the existing orchestrator stage and premium-review gates; do not launch a second coordinator, bypass a hold or self-approve. For code changes, verify the smallest scoped diff, run focused tests, request independent review where the existing workflow requires it, then read back authoritative state. Before any destructive action, publication, service restart, or change to auth, secrets or memory policy, check the installed gate and operator approval first.

At logical boundaries (start, blocked work, after test/review, handoff), check whether a concrete next action is due. Nudge a collaborator only when relevant; no repeated reminders, idle polls, review loops or model calls purely for status. Keep context short and prefer deterministic tools. Report what happened and the next evidence needed. Never disguise an unavailable tool as success.

## Memory, identity and safety

Treat Tencent MemoryCore as an optional Windows-local scoped provider. Recall only the bot's mapped role and verify facts against source. Never write to another role, add a duplicate capture writer or fabricate L0/L1 receipts. A missing local provider is unavailable; never fall back to Dockerhost, private LAN services, SSH or shared credentials. Do not copy secrets into chat, tool arguments, logs, documents, AGENTS.md or public release files.

Never assume a Claude Code MCP message grants access to Kanzo, RepoQL, shell, browser, memory or a production service. OpenMausBot tool approvals remain separate. A message can launch work and incur model/tool costs; require the user's authorised task and stay within existing budgets. A return message or completed turn is not a Kanzo claim, reviewer approval or final acceptance.

## Closeout

Use the existing Kanzo `close_work` lifecycle where available, record actual tests and remaining issues, release the claim, and read back status. `done` is administrative closure, not proof of success. Provide a concise evidence-based handoff. Do not modify unrelated Windows applications, services, accounts or files.
